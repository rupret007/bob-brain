# Conversation and conductor admission

The saved owner turn selects a server-owned reply contract. Requested writing
has an artifact and separate assistant commentary; its temporal or first-person
language is not an application dispatch receipt. Concrete unsupported application
effects remain guarded in both fields. Resource facts come from the shared
capability registry and timestamped observations. A supplied catch-up receipt is
reported evidence, bound to its receiver, and cannot authorize work. Its resume
cursor is exclusive. A later correction can withdraw that evidence.

`state/resource_capabilities.py` is shared by advice, conversation routing and
bounded report admission. Authentication does not establish quota, billing,
quality or access through a different adapter. Native Dot/Grok handoffs remain
owner-relayed and unaccepted until supported receiver evidence exists.

An operator can select a pre-admitted envelope using the private
`conductor/state/generation-policy.json` with `budget_id`, absolute
`accounting_root` and `purpose: product`. Only the operator creates or changes
the corresponding `generation-budgets/<id>.json`. Chat text and HTTP request
fields cannot create an allowance. Explicit provider selection supports
`provider_mode: only`; the existing default allows admitted fallback.

Every metered HTTP attempt, including retries, reserves against the shared
locked goal ledger before transport. Unresolved calls retain their conservative
reservation. Known charges never decrease. Native invocations have a separate
counter and bounded runtime; their internal requests and invoice charges may be
unknown. Source restrictions, provider eligibility, deadlines, held assignments
and replay identities survive restarts. Direct service calls observe the same
private policy even when not reached through the conversation wrapper.

Stop, hold, cancel, context correction and removal remain usable with expired
or malformed generation settings. New generation and task dispatch fail closed.
While this goal policy is selected, only the bounded report executor carries a
supported durable job allowance. Generic queued/claimed tasks remain unable to
start through that policy; their original receipts stay available. Without a
goal policy, existing worker admission still applies. A completed goal's policy
must be explicitly retired by its operator, preserving all original task and
generation receipts rather than silently resetting their budgets.

Bounded reports capture current project/task evidence, verify tracked source
bytes against the recorded commit, and read the dedicated Andrea bridge health
endpoint when configured for the real data root. The coverage document names
missing or partial evidence. Health does not prove a text was delivered. The
worker receives only the bounded immutable inputs and returns its assigned
artifact through the existing one-attempt task lifecycle.

Release fixtures remove real goal attribution; they must not consume a real
allowance using mock calls. Real isolated voice HTTP restores its validated
controller identity. Live controller calls through the normal server remain
charged to the shared goal and may conservatively consume the standalone HTTP
ceiling too. Native voice sessions retain their separately disclosed billing
uncertainty. No metadata check or unit test proves a real executor result or
comparative conversational quality.

Resource advice composes standalone server evidence statements with proposed
reasoning. The evidence namespace includes only projected current owner facts,
attributed to their source/revision rather than treated as operational authority.
Unavailable routes constrain both structured recommendations and bounded prose
checks. If reasoning fails, only complete evidence statements survive, with an
explicit incomplete-answer notice and rejected-block receipts; no proposal is
accepted. These checks do not certify arbitrary semantic truth. Delivered-answer
evaluation and actual completed product work remain separate required evidence.
