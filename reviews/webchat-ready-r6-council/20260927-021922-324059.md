### Conductor Parity Critique (run council on chat command, plain-English ops)

**What is wrong:**

3.  **Missing Council Cancellation:** As MiniMax points out, there's no explicit way to cancel a pending council request once initiated, leading to a poor user experience if the user changes their mind.

**What I would change:**

*   **Secure Council Execution:**
    *   Modify `webchat/job_queue.py` to pass the council question as a distinct argument to `council.py` rather than embedding it directly in a shell command.
    *   Update `conductor/services/council.py` to accept the question as a command-line argument, ensuring it's treated as data, not executable code.
    *   Implement a fixed runner that uses argument arrays (e.g., `subprocess.run(["python3", "conductor/services/council.py", "--question", question_text])`) to prevent shell injection.

*   **Full Conductor Lifecycle Reporting:**

    *   Investigate and fix the discrepancy between `HANDBACK-LOG.md` and `HANDBACK-SUMMARY.md` regarding new turns.
