## Top 3 Ranked Fixes

### 1. Gate services tests behind a flag (services/test_services.py, webchat/self_improve_tick.sh)
Current tick runs all three suites every interval. Instead, run services tests on a slower cadence (e.g., every 3rd tick or hourly):

```bash
# In self_improve_tick.sh
SERVICES_RC=0
if (( $(date +%_H) % 3 == 0 )); then  # run every 3rd hour
  python3 conductor/services/test_services.py >>/tmp/webchat-self-improve-tests.txt 2>&1 || SERVICES_RC=$?
fi
```

Otherwise the mini tick duration grows from ~2 min to ~5+ min, risking launchd timeout.

### 2. Validate `service_screen_count` does not leak structural data (services/live_dashboard.py)
The `service_screen_count` field exposes screen count derived from `service_screens`. If `service_screens` ever holds screen names or IDs, this count becomes intelligence. Add a comment or rename to `_count_hint` to signal it's a heuristic, not a stable ID:

```python
# line 285 in live_dashboard.py
"service_screen_count_hint": live_ops.get("service_screen_count", len(screens)),
```

### 3. Test CSS `color-mix` fallback for older WebViews (webchat/static/style.css)
The inline `code` contrast uses `color-mix(in srgb, ...)`, CSS Color Level 4. iOS <16 and Android WebView <107 lack support. Add a plain fallback:

```css
.message.assistant .body code {
  font: 0.92em ui-monospace, SFMono-Regular, Menlo, monospace;
  background: var(--surface-2);  /* fallback */
  background: color-mix(in srgb, var(--surface-2) 55%, var(--text) 8%);
  padding: 2px 6px;
  border-radius: 6px;
  border: 1px solid var(--line);  /* fallback */
  border: 1px solid color-mix(in srgb, var(--line) 70%, transparent);
  color: var(--text);
}
```
