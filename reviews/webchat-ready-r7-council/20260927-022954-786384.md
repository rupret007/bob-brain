### gemini-2.5-flash
PROPOSAL:

The core problem is Web Bob's reliability and user experience on mobile, particularly regarding real-time updates, handoff, and conductor parity. The current design suffers from information overload and a lack of structured data for critical operational insights.

My single best recommendation is to implement a robust, structured live operations event stream that feeds both the dashboard and the Web Bob UI. This stream will be the single source of truth for job status, model activity, and handoff digests, enabling real-time updates without polling or parsing unstructured logs.

Here are the top 3 ranked, concrete fixes:

1.  **Structured Live Operations Events:**
    *   **Risk:** Unstructured log parsing is brittle and inefficient, leading to stale or inaccurate dashboard/UI data.
    *   **Fix:** Modify `conductor/services/job_runner.py` and `conductor/services/providers.py` to emit structured JSON events (e.g., `job_started`, `job_progress`, `job_finished`, `model_reply_start`, `model_reply_end`) to a new `conductor/live_events.json` file. This file will be a rolling buffer of recent events. The `dashboard_updater` will consume this, and Web Bob's UI will fetch it directly for real-time updates. This replaces `log_tail` as the primary source for live status.

2.  **Handoff Digest Every Turn:**
    *   **Risk:** Incomplete or delayed handoff information can lead to Bob or Web Bob duplicating work or losing context.
    *   **Fix:** Implement `compact_digest()` in `conductor/webchat/chat_handler.py` to generate a concise summary of the current conversation state, running jobs, and pending actions. This digest will be appended to `conductor/handback/HANDBACK-LOG.md` and used to update `HANDBACK-SUMMARY.md` *after every successful Web Bob reply*. This ensures Bob always has the latest context.

3.  **Bottom Tab Bar + Quick Chips:**
    *   **Risk:** The current mobile UI is cluttered and not optimized for phone use, hindering usability and conductor parity.
    *   **Fix:** In `conductor/webchat/static/index.html` and associated CSS/JS, implement an iOS-style bottom tab bar with "Chat", "Jobs", "Models", "Songs", and "Settings" tabs. Above the chat composer, add quick-action chips for "Status", "Start round", "Ask council", and "New song". These chips will trigger corresponding actions via API calls, making conductor functions accessible and mobile-friendly.

These fixes directly address the requirements for structured live ops, continuous handoff, and an improved mobile UX, while also laying the groundwork for conductor parity.
