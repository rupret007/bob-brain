## Proposals
### Codex
**Vote: STATE primary for Jobs; handback prose supplies takeover context.** Make that conditional on freshness and consistency: the supplied implementation does not yet support the “zero-loss” claim in `reviews/WEBCHAT-READY-R8-DESIGN.md`. Jobs should display one validated STATE snapshot with its observation time; stale or unavailable data must appear as unknown.

Top three fixes, ranked:

1. **Make ledger updates transactional and corruption visible.** In `state/ledger.py`, inbox, decisions, chat turns, and live sync independently load, modify, and save the entire document. Atomic replacement prevents partial files but does not prevent concurrent updates from losing each other. Use a lock spanning read–validate–modify–write, add a monotonic revision, and validate the schema. `load_state()` must distinguish missing state from corrupt state rather than silently returning defaults that a later save can overwrite. Acceptance: simultaneous inbox append and live sync preserve both updates; malformed JSON remains preserved and produces an explicit unavailable state.

2. **Separate heartbeat freshness from job age; derive Jobs from STATE directly.** `sync_from_live_ops()` treats `started_at` as a heartbeat, so a healthy job running longer than 600 seconds can be marked stalled. Store actual heartbeat and observation timestamps; distinguish running, stalled, stopped, and unknown. `public_slice()` and `try_status_reply()` currently read `NOW.md` separately from STATE, permitting mixed revisions. Derive `now_line` from the same snapshot and select a live job explicitly: the first row can be inactive while another job is live. Acceptance: a healthy 20-minute job stays running; expired observations show unknown; Jobs and status agree on revision.

3. **Replace “since last read” heuristics with an acknowledged event cursor.** `write_catchup()` filters commits and review files by time but repeatedly includes historical completed asks and chat turns. Its 25-item cap and prefix deduplication can hide distinct events. Add sequenced events, an explicit acknowledgement cursor, and a visible overflow count with access to remaining items. Preserve current blockers separately from unread events. Treat inbox text as attributed, untrusted requests—not execution authority. Acceptance: repeated reads, overflow, and similar-prefix events neither silently lose nor falsely acknowledge information.

These are draft recommendations only; no changes applied.

**My ranked changes**

1. Transaction-wide serialization, validated state, and recoverable corruption handling.
2. Real heartbeat/freshness fields and deterministic active-job selection. `sync_from_live_ops()` inspects only the first job when choosing NOW, potentially reporting idle despite another live job.

### MiniMax-M2.7
## Critique of Alignment Design + Proposals

### Critical flaws in `state/ledger.py`

**1. Heartbeat/Staleness Confusion (High)**
`STALL_SECONDS = 600` triggers on elapsed time, not heartbeat age. In `sync_from_live_ops`, line 163, if `started_at` parses, `heartbeat = launched_ts`; if parsing fails, `heartbeat = now - elapsed_seconds`. A healthy job running 20 minutes gets marked `stalled` because `elapsed_seconds > 600`. This poisons `write_catchup`'s progress list.

**2. now_line Derivation Inconsistency (High)**
`sync_from_live_ops` writes `NOW.md` from the first job in `jobs_out` list order, but doesn't filter by `live=True` first. `write_catchup` reads `NOW.md` separately, creating split-brain: "Idle on mini" can overwrite a still-running job's status.

**3. Silent Default on Corruption (Medium)**
`load_state()` returns `default_state()` for missing *or* corrupt JSON, then `save_state()` overwrites the corrupt file with defaults, losing evidence. No distinction between "never existed" and "was tampered with/truncated."
