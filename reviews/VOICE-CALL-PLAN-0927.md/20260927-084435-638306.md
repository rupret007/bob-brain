**Cursor’s direction is workable, but its streaming, cancellation, and latency claims need qualification.**

- **Original Codex research:** `conductor/reviews/VOICE-CALL-RESEARCH.md/20260927-041814-759282.md` substitutes Zipformer/Kokoro for the requested Whisper/macOS TTS. Retain its transport design, but treat those engines as optional alternatives. Hardware, latency, and engineering estimates remain unverified; NO-QUORUM is not validation.

- **Cursor—STT:** A loaded Whisper model does not establish reliable streaming. `whisper_stream.py` needs overlapping windows, stable-prefix commitment, revised partials, endpoint finalization, and silence/hallucination filtering. Choose **whisper.cpp** initially and benchmark the actual Mac; its own [README](https://github.com/ggml-org/whisper.cpp/blob/master/README.md) describes its streaming example as naive.

- **Cursor—TTS:** `macos_tts_stream.swift` should use [AVSpeechSynthesizer buffer callbacks](https://developer.apple.com/documentation/avfaudio/avspeechsynthesizer/write(_:tobuffercallback:)), with clause segmentation, PCM resampling, bounded queues, and cancellation. This supports incremental audio delivery; first-buffer latency still requires measurement with the installed voice.

- **Both—barge-in:** `turn_id` cannot remove audio already buffered in Safari. `voice_client.ts` needs immediate local playback suppression, coordinated cancellation, and bounded transport buffering. `voice_session.py` must distinguish generated, transmitted, and approximately played speech; “delivered” does not prove heard.

- **Cursor—tools/security:** Cancelling generation cannot undo tool effects. Add operation IDs, explicit tool lifecycle events, no automatic replay after reconnect, and policy enforcement preserving the user’s prohibitions. Never execute tools from provisional STT. Authenticate signaling and validate origins.

- **Tests/file plan:** Keep everything under `proposals/voice-call/`. Specify transcript revision/event ordering and a foreground-only initial scope. Test echo-induced interruptions, long pauses, disconnects, stale audio, and tools completing after barge-in. Measure p95 physical speech-end → audible meaningful response and interruption → silence on iPhone speaker/AirPods over Wi-Fi/cellular. Report tool-result latency separately; a filler acknowledgement must not satisfy the 1.5-second target.

## Critique (Codex research vs Cursor build-on)

**Codex (sherpa Zipformer + MLX 3B + Kokoro)**  
- **Wrong stack for “Web Bob”:** Adds a second on-device LLM (MLX 3B) instead of the existing chat/tool backend—duplicate auth, memory, and behavior.  
- **Unmeasured latency:** 1.2s is arithmetic, not benchmarks; Kokoro/MLX cold start and RAM on an unverified Mac mini are ignored.  
- **Missing integration:** No `bob_adapter`, tool lifecycle, or how partial STT reaches the current session store.  
- **Unsafe simplification:** “Invalidate stale chunks” without defining what counts as *delivered* speech when tools mutate state mid-turn.

**Cursor (Pipecat + whisper.cpp + `MacSpeechBridge.swift`)**  
- **STT mismatch:** Windowed whisper.cpp is not streaming ASR; overlapping 250–500ms windows risk repetition, drift, and late finals—bad for barge-in and live transcript UX (`voice/whisper_adapter.cpp`).  
- **TTS risk:** `AVSpeechSynthesizer.write` often batches by utterance; “short-clause” streaming may still miss sub-1.5s first audio unless you prove buffer callbacks fire early with an offline voice.  
- **Ops / safety:** Python + FastAPI + aiortc + Swift bridge + cpp build is fragile for one Mac mini service; no versioning, crash isolation, or mic-permission recovery in `voice/server.py`.  
- **Duplex echo:** Proposals assume Silero VAD on server fixes barge-in; with **mic on iPhone** and **TTS played on iPhone**, server VAD does not cancel acoustic echo—need client playout ducking/mute (`voice/client.ts`) and measured interrupt &lt;200ms.  
- **Tools:** Async tools + cancel is correct, but no rule for rejecting stale tool results by `turn_id` in `voice/bob_adapter.py` (completed side effects still dangerous).

**What I would change**  
Keep Pipecat/SmallWebRTC + data channel for transcript/turn IDs; **do not** add MLX. Benchmark whisper.cpp vs **faster-whisper** on received Opus frames before locking `whisper_adapter`. Prefer **one runtime** (Python + optional small native STT lib) over Swift unless macOS TTS wins on measured first-buffer latency. Phase 0: Tailscale ICE/UDP + loopback latency harness in `tests/voice/` before any model work. Gate rollout on p95 metrics from `docs/voice-call-test-plan.md`, including speakerphone/AirPods and tool-heavy turns.
