### Live Call Utterance Queue Race Condition
**What is wrong:** In `conductor/webchat/static/app.js`, the `drainCallQueue` function uses a shared `callDrainRunning` flag. When a new call session starts, `callDrainRunning` is reset to `false` (line 583). If a previous `drainCallQueue` is still awaiting `handleCallUtterance` (line 525), it can resume, consume an utterance from the *new* session's queue, and then `handleCallUtterance` (line 550) will discard it because `callSession.id` no longer matches the `sessionId` from the old drain's context.
**What to change:** Store `callDrainRunning` and `callUtteranceQueue` as properties of the `callSession` object. Ensure that `drainCallQueue` checks `callSession.id` *before* processing any utterance and that `callSession.busy` is reset in a `finally` block within `handleCallUtterance` (line 573).

### Music Coach Regex Over-matching
**What is wrong:** In `conductor/webchat/music_notebook.py`, the `_MUSIC_COACH_RE` regex uses `\b(?:...|intro|pre-?chorus|capo|riff|vamp)\b` (line 118). While `\b` provides word boundaries, the `intro` and `capo` terms are too generic. For example, "introduce" or "introitus" would match `intro`. **What to change:** Refine `_MUSIC_COACH_RE` to be more specific for ambiguous terms, potentially requiring additional musical context or using more precise token matching.
