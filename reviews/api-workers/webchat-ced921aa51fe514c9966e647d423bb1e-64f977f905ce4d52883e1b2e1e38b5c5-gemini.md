### Findings

The audit of the dispatch, evidence collection, and result acceptance systems reveals a potential regression path where an API worker task could be dispatched without the necessary repository evidence.

1.  **Dispatch Context Creation**: In `webchat/worker_assignment.py`, the `plan()` function creates tasks for API workers based on "ongoing work". It can source this work from active jobs in the queue, running processes, or unverified project lanes detected via `screen`.
2.  **Evidence Dependency**: In `services/dispatch_worker.py`, the `execute()` function for an API worker task (e.g., `audit`, `test-writing`) calls `report_repository()` to find the correct code checkout. This function relies on the `source_job_id` to locate the source job's `worktree`.
3.  **The Gap**: The `plan()` function in `webchat/worker_assignment.py` can create an API worker task based on an "unverified" project lane from `screen` or a deployed project context. In these cases, the created task has a `prompt` describing the project context but is not linked to a concrete source job (`source_job_id=None`).
4.  **Execution Failure**: When `dispatch_worker.py` executes this task, `report_repository()` is called. Since `source_job_id` is `None`, it returns `(project, None)`. The subsequent call to `api_worker.evidence()` is blocked because the repository path is `None`, leading to a `ResultRejected` exception with the message "The assigned source job has no available worktree for repository evidence".

This constitutes a regression: a user request to assign API workers to an observed-but-not-job-linked project context results in a task that is guaranteed to fail upon execution. The system correctly prevents execution without evidence but does not prevent the dispatch of such a task.

The fix is to ensure that `webchat/worker_assignment.py` only creates API worker tasks of `REPORT_KINDS` if a `source_job_id` is available. Contexts derived from unverified lanes or deployment pins, which lack a source job, should not generate these tasks.
