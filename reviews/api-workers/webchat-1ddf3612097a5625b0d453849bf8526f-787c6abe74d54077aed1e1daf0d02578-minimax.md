# Web Bob Dispatch System Regression Review

## Findings

### 1. Critical Path: `services/jobs.py` → `can_assign()` Logic

**Issue 1: Lane Assignment Race Condition**
```python
# services/jobs.py:288-295
def can_assign(spec, lane, active, health):
    if health[lane]["state"] != "ready" or any(r.get("engine") == lane for r in active):
        return False
    if spec["kind"] == "coding" and lane in ("gemini", "minimax"):
        return False
    # ... more checks
    return len(active) < 5
```

The `active` list is built from `jobs()` state at tick time, but `launch_record()` is called after the check. Between check and launch, another tick could assign the same lane. **No atomic locking around the assign-then-launch sequence.**

**Issue 2: WebJam Singleton Violation Window**
```python
# services/jobs.py:295-296
if spec["kind"] == "coding" and spec["project"] == "WebJam":
    if any(r.get("project", "").startswith("WebJam") and r.get("kind") == "coding" for r in active):
        return False
```
The `startswith("WebJam")` check would also match "WebJamCI" or "WebBob" if added later. Uses string prefix matching instead of exact project enumeration from `PROJECTS`.

### 2. Critical Path: `services/lanes.py` → `slot()` Context Manager

**Issue 3: Shared Lock Starvation**
```python
# services/lanes.py:55-70
@contextlib.contextmanager
def slot(lane):
    if lane not in ("gemini", "minimax"):
        with lock("lane-" + lane, blocking=False):
            yield
        return
    usage = budget.check(lane)
    limit = 1 if usage["tier"] == "slow" else task_queue.capacity(lane)
    with lock("lane-" + lane, blocking=True, shared=True):
        for index in range(limit):
            # ... try each slot index
```
- Uses `blocking=True` (shared lock) for the outer context
- Inner slots use `blocking=False`
- If all inner slots are taken, the outer shared lock is held while retrying
- On high-contention API traffic, this can cause the shared lock to be held indefinitely

**Issue 4: `refresh()` Called Without Slot Context**
```python
# services/jobs.py:318 (in tick())
health = lanes.refresh()  # Cursor login checked every tick, even with an empty queue.
```
`refresh()` calls `budget.check()` which can raise `BudgetExceeded`, but this exception propagates up and crashes the tick loop instead of marking the lane as `budget_exhausted`.

### 3. Critical Path: `services/dispatch_worker.py` → `setup()` Prompt Injection

**Issue 5: Redaction Bypass via Context Injection**
```python
# services/dispatch_worker.py:89-94
if context:
    lines.append("")
    lines.append("CONTEXT:")
    lines.append(context)
lines.append("")
lines.append("TASK:")
lines.append(task.get("prompt", ""))
```
The `context` parameter comes from `EVIDENCE.txt` which is written by `setup_record()` in jobs.py. If a malicious file is added to `evidence` list in backlog.json, it gets written without redaction pass through `redact()`, only through Python's default string handling.

**Issue 6: Model Deny-List Inconsistency**
```python
# services/dispatch_worker.py:27
if worker not in ("codex", "claude", "cursor", "minimax", "gemini"):
    raise RuntimeError("Unsupported API worker; Grok/xAI is never allowed")
```
But `services/jobs.py:289` allows `"gemini"` and `"minimax"` for non-coding tasks. The worker itself doesn't enforce project-specific lane restrictions.
