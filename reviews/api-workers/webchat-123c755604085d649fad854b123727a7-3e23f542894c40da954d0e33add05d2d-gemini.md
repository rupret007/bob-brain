Based on my audit of the repository, I have identified a potential issue related to job completion and have formulated a concrete implementation plan.

### Audit Findings

The task name `lane-webbob-texting-jobcomplete-fix-1107` suggests a problem with job completion, possibly related to texting. However, the provided file list (`services/dispatch_worker.py`, `services/result_acceptance.py`, etc.) points strongly toward the general task execution and acceptance lifecycle, rather than the texting-specific features in `webchat/texting.py`.

A key finding comes from `services/test_api_workers.py` and `services/test_result_acceptance.py`, which both reference a fixture named `texting_jobcompletion_1035.json`. The tests confirm that for tasks requiring test drafts (like `test-writing`), an exploratory answer without concrete deliverables is deterministically rejected by `result_acceptance.check_deliverables` before it can be published or even semantically reviewed by another model. This strict acceptance gate is a critical part of the system's reliability.

The `result_acceptance.py` module defines `check_deliverables`, which enforces that tasks of kind `test-writing` or those containing phrases like "Review and regression test-case drafts" must include either structured test case descriptions (Target, Setup, Action, Expected) or executable test code. If these are missing, a `ResultRejected` exception is raised, causing the task to fail.

The current implementation of `check_deliverables` is robust but could be made more explicit. The logic for determining if a task needs test drafts is encapsulated in `needs_test_drafts`, which checks the task `kind` and searches for a specific phrase. While effective, this could be brittle if new, similar task types or phrasings are introduced.

### Implementation Plan

To harden the job completion and acceptance process, I propose adding an explicit `deliverables` field to the task queue record. This will make the deliverable requirement a deterministic part of the task definition, removing ambiguity from prompt parsing.
