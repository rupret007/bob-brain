### 2. services/lanes.py — `slot()` Context Manager (lines ~155-175)

**Finding**: The exit-stack pattern for acquiring lane slots is fragile.

```python
for index in range(limit):
    stack = contextlib.ExitStack()
    try:
        stack.enter_context(lock("lane-" + lane + "-" + str(index), blocking=False))
    except BlockingIOError:
        stack.close()  # ExitStack.close() is idempotent but not widely known
        continue
```

**Issue**: If `limit` is 0 (possible when `tier == "slow"` and `capacity()` returns 0), the loop exits without yielding, and the `BlockingIOError` is raised *outside* the loop. However, this is likely intentional—it signals full lane exhaustion.

### 3. services/api_worker.py — `extract()` Function (lines ~50-90)

**Finding**: Reasoning-stripping logic has an edge case that can cause false `RuntimeError`.

```python
if reasoning and not content.strip().startswith("MiniMax reasoning-only answer"):
    # ... reasoning split path
else:
    candidates = data.get("candidates") or []
    if not candidates or candidates[0].get("finishReason") != "STOP":
        raise RuntimeError("Gemini missing, blocked, or truncated final answer")
    text = "\n".join(p.get("text", "") for p in candidates[0].get("content", {}).get("parts", [])
                     if not p.get("thought")).strip()
    if len(text) < 20:
        raise RuntimeError("empty or unusably short final answer")
```

**Issue**: If `finishReason == "STOP"` but the model included *legitimate short answers* (e.g., "PASS", "BLOCKED", single-line confirmations under 20 chars), this raises a false error.

**Regression test**:
```python
def test_short_legitimate_answer_not_rejected():
    """A genuinely short answer (e.g., 'PASS' or 'BLOCKED: reason') must not error."""
    data = {
        "candidates": [{
            "finishReason": "STOP",
            "content": {"parts": [{"text": "PASS"}]}
        }]
    }
    # extract("gemini", data) should return "PASS", not raise RuntimeError
    pass
```

### 4. services/budget.py — `reserve()` Worst-Case Bound (lines ~73-90)

**Finding**: The conservative worst-case bound is sound but could silently over-reserve for small inputs.

```python
rate = (2.50, 15.0, .25, 2.50) if model_id == "gemini-2.5-pro" else RATES[lane]
bound = ((len(prompt.encode("utf-8")) + 4096) * max(rate[0], rate[3]) + max_tokens * rate[1]) / 1_000_000
```

**Observation**: For a 100-token prompt with `max_tokens=100`, the bound adds 4096 *rate which dominates the actual cost. This is conservative but means small requests pay ~40x overage in worst-case estimate.
